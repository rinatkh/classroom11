# Интервью: вопросы и короткие ответы

Используйте сначала только вопрос. Короткий ответ нужен преподавателю для сверки; после него попросите ученицу привести пример.

1. **OSI — это точное описание реализации интернета?**

   Нет. Это полезная модель из семи уровней. Практический internet stack чаще описывают моделью TCP/IP, а границы реализаций не всегда совпадают с OSI.

2. **Что происходит при encapsulation?**

   Каждый уровень добавляет служебную информацию для своей задачи: HTTP-данные попадают в TCP segment, затем в IP packet, затем в link-layer frame.

3. **Зачем DNS, если приложение работает с URL?**

   Для сетевой доставки обычно нужен IP. DNS связывает имя вроде `api.example.com` с адресами и другими записями.

4. **IP и port — одно и то же?**

   Нет. IP выбирает сетевой интерфейс/узел, port помогает ОС направить transport traffic нужному процессу или socket.

5. **Что означает `0.0.0.0:8080` в `Listen`?**

   Слушать порт 8080 на всех локальных IPv4-интерфейсах. Это не адрес, который обычно вводят клиенту как destination.

6. **Что гарантирует TCP?**

   Надёжный упорядоченный поток байтов между endpoints при живом соединении. TCP не сохраняет границы приложенческих сообщений.

7. **Назовите three-way handshake.**

   SYN → SYN-ACK → ACK. Стороны синхронизируют начальные sequence numbers и подтверждают готовность соединения.

8. **Зачем sequence number и ACK?**

   Sequence numbers отмечают позиции байтов; ACK сообщает, какой следующий байт ожидается. Это позволяет обнаружить пропуск и повторить передачу.

9. **Flow control и congestion control — одно?**

   Нет. Flow control защищает receiver от переполнения; congestion control снижает нагрузку на сеть.

10. **FIN и RST?**

    FIN — упорядоченное завершение направления передачи; RST — немедленный сброс состояния соединения.

11. **Почему TCP может быть в TIME_WAIT?**

    Активно закрывшая сторона некоторое время сохраняет состояние, чтобы старые сегменты не попали в новое соединение и финальный ACK можно было повторить.

12. **TCP keepalive и HTTP keep-alive?**

    TCP keepalive проверяет простаивающее соединение на уровне ОС. HTTP persistence позволяет отправлять по соединению следующие HTTP requests.

13. **Что UDP гарантирует?**

    UDP сохраняет границу датаграммы и checksum, но не гарантирует доставку, порядок или повторную передачу.

14. **Почему HTTP/3 может работать поверх UDP и быть надёжным?**

    Надёжность, порядок внутри streams, congestion control и TLS реализует QUIC поверх UDP.

15. **HTTP — это формат байтов или смысл запросов?**

    HTTP задаёт semantics: methods, fields, status. Представление различается: текст HTTP/1.1, binary frames HTTP/2, QUIC frames HTTP/3.

16. **Зачем `Host` в HTTP/1.1?**

    Чтобы сервер отличил виртуальные hosts на одном IP/port. Запрос без Host считается некорректным.

17. **Как HTTP/1.1 узнаёт длину body?**

    Например, по `Content-Length`, chunked transfer coding или правилам конкретного ответа. Закрытие соединения — менее удобный вариант framing.

18. **Почему HTTP/1.1 pipelining почти не решило параллельность?**

    Ответы должны идти в порядке запросов, поэтому медленный первый ответ задерживает следующие.

19. **Что такое stream в HTTP/2?**

    Независимая логическая последовательность frames одного request/response внутри общего connection.

20. **Что даёт HTTP/2 multiplexing?**

    Frames разных streams чередуются в одном TCP-соединении, поэтому не нужно ждать полного application response перед передачей другого.

21. **Почему loss одного TCP segment влияет на HTTP/2 streams?**

    TCP выдаёт приложению упорядоченный поток; пока пропуск не восстановлен, более поздние байты всех streams не доступны HTTP/2.

22. **Что даёт TLS?**

    Конфиденциальность, целостность и проверку identity сервера по сертификату. Авторизацию пользователя TLS сам по себе не выполняет.

23. **Зачем в TLS и симметричная, и асимметричная криптография?**

    Асимметричные механизмы помогают аутентифицировать и согласовать секрет; симметричное шифрование эффективно защищает основной трафик.

24. **Что проверяет client в certificate?**

    Цепочку к доверенному root, имя сервера, срок действия и допустимое назначение сертификата.

25. **SNI и ALPN?**

    SNI передаёт имя сервера для выбора сертификата. ALPN выбирает application protocol, например `h2` или `http/1.1`.

26. **Почему `http.Client` нужно переиспользовать?**

    В его Transport хранится pool connections. Переиспользование уменьшает новые DNS/connect/TLS handshakes.

27. **Почему нужно закрывать `response.Body`?**

    Это освобождает ресурсы. Для reuse HTTP/1.x body обычно нужно дочитать до конца и закрыть.

28. **Что показывает `httptrace.GotConnInfo.Reused`?**

    Получено ли уже существовавшее connection из pool или создано новое.

29. **Где поставить timeout?**

    На границе операции. Общий `Client.Timeout` прост, а context позволяет связать отмену с жизненным циклом входящего request и задать deadline конкретной операции.

30. **Что раньше: HTTP handler или TCP accept?**

    Сначала сеть устанавливает/принимает transport connection и читает HTTP representation; затем `net/http` создаёт `http.Request`, выбирает handler и вызывает его.
