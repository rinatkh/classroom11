# Карта протоколов занятия

## В браузере или Go client

```text
URL
├── имя узла ── DNS ── IP
├── scheme https ── TLS
└── path/query ── HTTP request

HTTP/1.1 или HTTP/2
└── TLS (для https)
    └── TCP
        └── IP

HTTP/3
└── QUIC (включает TLS 1.3 handshake)
    └── UDP
        └── IP
```

Это карта ответственности, а не точная схема каждого байта. Реальная сеть имеет дополнительные детали: Ethernet/Wi-Fi, NAT, прокси, балансировщики и кеши.

## Где искать ошибку

| Симптом | Возможный слой | Первый вопрос |
|---|---|---|
| `no such host` | DNS | разрешается ли имя? |
| `connection refused` | TCP | кто-нибудь слушает этот IP:port? |
| `i/o timeout` | несколько этапов | какой timeout сработал и на каком событии? |
| `connection reset by peer` | TCP | другая сторона аварийно закрыла соединение? |
| `x509: certificate ...` | TLS | имя, срок и цепочка доверия корректны? |
| `404 Not Found` | HTTP/application | правильны ли method/path и данные? |

## Не путать одинаковые слова

| Термин | Значение |
|---|---|
| TCP stream | непрерывная последовательность байтов |
| HTTP/2 stream | логический двунаправленный поток frames внутри одного соединения |
| TCP keepalive | проверка жизнеспособности TCP-соединения на уровне ОС |
| HTTP keep-alive | сохранение соединения для следующих HTTP-запросов |
| TLS record | защищённая порция данных TLS |
| HTTP/2 frame | минимальная структурная единица HTTP/2 |
