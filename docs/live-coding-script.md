# Live coding script — занятие 11

Ориентир: 75–95 минут практики после теории. Не пытайтесь одновременно объяснять все уровни сети. В каждом шаге сначала сформулируйте один вопрос, затем запустите код и только после вывода назовите термин.

## Перед началом — 3 минуты

```bash
go version
make ci
```

Ожидаем Go 1.22+ и зелёные проверки. Покажите структуру `cmd`: это шесть независимых лабораторий, а не один production-сервис.

## 01. TCP echo — 18 минут

Откройте:

```text
cmd/01_tcp_echo/server/main.go
internal/networklab/tcp.go
cmd/01_tcp_echo/client/main.go
```

1. На `net.Listen` скажите: «ОС связывает socket с локальным адресом и портом».
2. На `Accept` спросите: «Эта строка крутит CPU или ждёт?» Ожидаем: блокируется до подключения.
3. На `net.Conn` поясните: это двусторонний поток; он реализует `io.Reader` и `io.Writer`.
4. На цикле `Scanner` найдите framing `\n`.
5. Запустите server и client в разных терминалах.
6. Спросите: «Сколько TCP connections и сколько сообщений?» Ответ: одно connection, три логические строки.

Негативный эксперимент: временно уберите `\n` у клиента. `Scanner` продолжит ждать конец строки. Верните код до следующего шага.

## 02. UDP echo — 10 минут

Откройте `udp.go` рядом с `tcp.go`.

1. Найдите отсутствие `Accept`.
2. На `ReadFrom` покажите, что адрес приходит с датаграммой.
3. Запустите `make udp-server` и `make udp-client`.
4. Спросите, где реализована повторная отправка потерянной датаграммы. Ответ: нигде.

## 03. Raw HTTP — 14 минут

Откройте `BuildRawGET`. Прочитайте каждую строку request как данные, а не как Go API.

```bash
make raw-http
```

1. Покажите request line.
2. Покажите обязательный `Host`.
3. Посчитайте пустую строку `\r\n\r\n`.
4. Свяжите output с прошлым уроком: тот же `GET /health` дошёл до обычного handler.

Негативный эксперимент: замените `HTTP/1.1` на `HTTP/1.0` и уберите Host. Обсудите, почему сервер может принять старый формат, но это не современный контракт клиента.

## 04. `httptrace` и reuse — 16 минут

```bash
make http-trace
```

1. На первом запросе выделите `ConnectStart` и `GotConn reused=false`.
2. На втором найдите `GotConn reused=true`.
3. Закомментируйте `io.Copy(io.Discard, response.Body)` и обсудите, почему reuse становится менее надёжным.
4. Верните чтение и закрытие body.

Связь с собеседованием: попросите ученицу объяснить, почему новый client на каждый запрос дороже.

## 05. TLS + HTTP/2 — 12 минут

```bash
make tls-http2
```

Разделите три строки output: HTTP version, TLS version, ALPN. Подчеркните: это три связанных, но не одинаковых понятия. Откройте `InspectTLS` и найдите `response.Proto`, `response.TLS.Version`, `NegotiatedProtocol`.

## 06. Timeout — 10 минут

```bash
make timeouts
```

1. Сравните 150 мс server delay и 40 мс deadline.
2. Найдите `context.WithTimeout`.
3. Спросите: «Если это исходящий запрос из handler, откуда лучше взять parent context?» Ответ: `r.Context()`.
4. Измените timeout на 300 мс и убедитесь, что request успевает.

## Завершение — 8 минут

Откройте `docs/protocol-map.md` и попросите ученицу проговорить путь:

```text
URL → DNS → IP → TCP → TLS → HTTP → net/http → handler
```

Затем уточните: для HTTP/3 вместо TCP будет QUIC поверх UDP. Завершите пятью случайными вопросами из `docs/interview.md`.
